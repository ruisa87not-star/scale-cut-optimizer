# 卷材裁切優化器（React + C++ 桌面版）

這個版本以 Electron 封裝 React 介面，並由 C++17 原生程式計算排料。一般裁切的優先順序是：

1. 最少開新卷。
2. 最少產生低於可回收門檻的碎料。
3. 在前兩項相同時，盡量消耗現有餘料。
4. 在以上條件相同時，減少可回用餘料的段數；段數也相同時，優先保留較長的單段餘料。

不包含 Kerf／每刀損耗參數。

一般裁切以多種整卷組合搜尋、跨卷重新排料及小訂單的限額分支搜尋改善最大長度優先排法。1.3 版亦會檢查超過 80 卷的大訂單中的所有短尾料，避免它們被搜尋上限略過。特殊端段模式優先減少不可回收碎料、使用現有餘料，再比較新卷數；會保留合法的端段對接順序並重新配置一般裁切。搜尋有時間／節點上限，並非所有大型訂單都能保證數學上的全域最優。

例如 `1350×43、1100×42、1050×114、800×9、600×9、200×33、150×33`，每卷 `5000`、餘料門檻 `150`、沒有現有餘料時，1.2 版可用 `50` 卷完成（新卷數理論下限），不可回收碎料 `0`，可回收餘料合計 `1900`。

## 1.4：集中可回用餘料

算法不再因為已達最低卷數、零碎料就立即停止搜尋；還會比較餘料段數及各段長度。局部聯合重排會交換多件裁切，必要時從已用滿的卷借換裁切組合，保持全部訂單數量和原料核對一致。若不能把全部餘料集中成單條，會嘗試集中較小的分組。特殊端段對接鏈仍保持完整，普通裁切可以重新配置。

舊評分的搜尋結果亦會保留作為候選，再比較新結果；集中餘料不會覆蓋卷數、碎料或現有餘料利用率更好的候選。搜尋有時間及節點上限，不保證所有訂單都達到最少餘料段數。

對上方訂單，只調整 `150` 的數量，在相同設定下已驗證：

| 150 的數量 | 新卷數 | 可回用餘料 | 不可回收碎料 |
|---:|---:|---|---:|
| 33 | 50 | 1100＋800（2段） | 0 |
| 34 | 50 | 1750（1段，其餘49卷用滿） | 0 |
| 35 | 50 | 1600（1段，其餘49卷用滿） | 0 |

## 1.7：餘料批量新增與回收狀態標示

餘料庫存可同時填寫長度與數量（數量預設為 `1`），例如長度 `1500`、數量 `10`，一次新增 10 段獨立庫存，保留逐段移除與使用的方式。長度及數量須為正整數；每次最多新增 10,000 段，避免誤輸入大量數字令介面失去回應。匯入檔案格式保持不變。

Excel Visual Layout／視覺成品排料的「Reusable／可回收」狀態格使用黃色底色；實際餘料長度格仍用綠色，其他工作表、成品配色、卷號排序及 C++ 算法不變。

## 1.6：長度配色與排法排序

同一份方案中，不同成品長度分配不同底色，程式與 Excel 使用同一份配色；成品長度數字仍逐格保留。餘料和端段補位維持各自的顏色及文字標示，Visual Layout 不再顯示通用 Colour Label 圖例。

計算後會按裁切長度（由長到短）、各長度數量排列新卷，將完全相同的實體排法集中，讓主要長度與數量相近的配方相鄰。程式、Cut Recipes、Visual Layout 和 Pitch Joins 使用同一套新卷編號。排序只調整整卷顯示順序，不移動卷內任何裁切或端段，不改 C++ 算法、卷數、碎料及餘料總量；既有餘料保留原庫存編號。

## 1.5.1：精簡 Excel 視覺排料

Visual Layout／視覺成品排料不再插入每卷的「裁切指令」及空白列，卷號會連續排列。每段裁切長度、端段補位及餘料格維持不變；裁切段數較多時，仍保留必要續行。完整指令保留在 Cut Recipes／成品裁切配方，其他工作表和 C++ 算法不變。

## 1.5：裁切工作台介面

沿用 1.4 的 C++ 排料算法與 Excel 報告格式，重新整理操作介面：

- 左側輸入訂單及餘料，右側直接查看裁切結果；訂單數量可在清單中修改。
- 顯示開新卷數、不可回收碎料、可回用餘料段數及最長單段餘料。
- 視覺排料每格標示一段實際裁切長度，端段補位及餘料分開顯示。相同排法會合併展示並列出實際卷號；每件裁切與每卷明細仍可查閱。
- 可篩選含餘料、已用滿或含碎料的卷，並按長度或 `#卷號` 搜尋；另有逐卷明細及餘料庫存檢視。
- 修改訂單、庫存或設定後，舊結果會標示「需要重新計算」，並暫停匯出，避免新訂單與舊結果混用。
- 中英文介面、欄位錯誤提示、鍵盤焦點與窄視窗版面一併調整；沒有新增網絡字體或運行時依賴。

## 中文 / English 切換

右上角的「語言 / Language」選單可即時切換繁體中文與英文。切換不會清除訂單、餘料或計算結果；關閉後再開啟會記住上次選擇。

Excel 匯出會使用目前所選的語言，包括工作表名稱、裁切指令、視覺排料說明與狀態。裁切長度、數量及排料結果不受語言影響。

## 固定節距與中段對接

節距預設為 `50`，可在介面調整。一般訂單會按完整節距計算；若有端段需要與其他訂單共用，可輸入特殊規格 `總長-起始/結束`，例如：

- `160-30/30`：`30 + 50 + 50 + 30`
- `940-20/20`：`20 + 50 × 18 + 20`

當一個訂單的結束端段與另一個訂單的起始端段互補為一個節距（如 `30 + 20 = 50`）時，引擎只會在卷材**中間**的節距將它們對接。每卷的第一節與最後一節不會用於端段對接；這符合 5,000 長度、100 節的生產規則。節距模式啟用時，新卷長度與可用餘料長度必須是節距的整數倍。

1.3 版會先按端段對接相容性分組，再一起配置原料卷。加入第三種不相容的特殊規格（例如 `780-40/40`）不再令 `940-20/20` 與 `160-30/30` 失去互補組合搜尋。引擎會比較不同鏈長、整卷填充與多種子集配排，並略過重複的實際裁切方案；這是通用搜尋，沒有寫死特定訂單。

以下訂單在每卷 `5000`、節距 `50`、餘料門檻 `150`、沒有現有餘料時，1.3 版驗證結果為 **110 卷、可回用餘料 3900、不可回收碎料 1330**，共 643 件。1330 全部是必要的端段補位碎料，沒有低於門檻的尾料；原料核對為 `110 × 5000 = 544770 + 1330 + 3900`。

## 開發執行

在此資料夾內依序執行：

```powershell
corepack pnpm install
corepack pnpm native:build
corepack pnpm dev
```

`native:build` 會建立 `native/build/Release/cutting_optimizer.exe`，Electron 會透過安全的 IPC 將訂單資料交給這個原生引擎。此命令使用 Microsoft C++ Build Tools，不需要另行安裝 CMake。

## 建立可攜版 Windows 應用

```powershell
corepack pnpm package
```

輸出會位於 `release/`，包含 React 前端、Electron 外殼，以及 C++ 排料引擎。

## 匯入格式

- 訂單：`長度,數量`、`長度 × 數量`、`總長-起始/結束,數量`（如 `160-30/30,4`），或單一長度（一件）。
- 餘料：每行一段；Excel 使用第一欄。
- 支援 `.txt`、`.csv`、`.xlsx`。
- 貼上文字也支援中文分號 `；` 分隔訂單。逗號在訂單文字中表示「長度,數量」；有千位逗號時請用乘號格式，例如 `1,350 × 43`。

匯出報告包含總覽、成品裁切配方、視覺成品排料、實際裁切數量；特殊端段模式另有節距對接表。

視覺成品排料中，每個未合併的 Cell 代表一件裁切長度；例如 `1350×3` 會顯示 `[1350] [1350] [1350] [餘料 950]`。各格等寬，不代表長度比例；超過一行會續行，保留每一件裁切。端段補位獨立以橙色顯示，餘料以最後一格列出（餘料為 0 時省略）。
